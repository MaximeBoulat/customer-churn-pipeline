Overview

The project has three implemented stages: data catalog, preprocessing with Feature Store ingestion, and a SageMaker training pipeline. Curation runs separately; the repeatable pipeline starts from curated Parquet and ends with a model candidate awaiting manual approval. Batch inference and monitoring are future work.

Stages

  • : register raw data and produce typed, partitioned Parquet.
  • : split labeled data, fit preprocessing and ingest features.
  • : orchestrate preprocessing, ingestion, training, evaluation and conditional registration.

Infrastructure and execution

data-catalog/ owns the Glue database, raw table and Athena workgroup. pipeline/ owns the Feature Group, model package group and SageMaker pipeline together. Terraform sets up infrastructure; Python starts curation or a pipeline execution. There is no separate train-model deployment.

Storage

The team bucket supplies raw CSVs. The personal bucket holds curated data, run inputs, fitted preprocessing parameters, trained models and evaluations. The offline Feature Store uses the existing Learner Lab SageMaker bucket.

Team bucket/
└─ raw/cell2cell/                              source CSVs

Personal bucket/
├─ curated/cell2cell/{curated-version}/        curated Parquet
├─ athena-results/                            curation query outputs
├─ pipeline/
│  ├─ code/                                   uploaded Python files
│  └─ {execution-id}/
│     ├─ process/                             splits, IDs and fitted contract
│     └─ feature-store/                       ingestion report
└─ models/cell2cell/{model-version}/{execution-id}/
   ├─ <training-job-name>/output/model.tar.gz
   └─ evaluation/evaluation.json

Existing lab SageMaker bucket/
└─ features/{project-prefix}/cell2cell/{feature-version}/
   └─ <AWS-generated offline-store folders>/

Training reads the processed CSVs directly. Feature Store receives the same features but is not the training job's read path. Each registered model package records the URI of its run's fitted preprocessing parameters. SageMaker records execution status; this implementation does not add a manifest.
