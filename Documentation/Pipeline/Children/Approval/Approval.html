Feature overview

The pipeline registers a candidate as PendingManualApproval. After reviewing its evaluation, the operator approves the model and pins the files downstream inference needs. This is the hinge between training and production: an explicit choice of model, preprocessing and decision cutoff. It runs separately from the SageMaker pipeline and needs no additional Terraform resources.

Component analysis

Diagram

Key AWS actors and concepts

Model Registry holds the package's approval status. S3 holds the pinned files. approved_contract.json points to the exact model artifact, container image, preprocessing parameters and evaluation report; it also records the input schema and versions. The selected cutoff is in the pinned evaluation's threshold.value. The run manifest is not used or updated by this step.

Sequence analysis

Overview

Open the completed execution in SageMaker Studio and review its Evaluate step's report in S3: AUC, confusion matrix, selected cutoff, expected cost versus no contact, and whether the top-k fallback was used. Copy the execution ARN. The script finds the registered package and associated files automatically.

From the repository root, with the project's environment loaded:

python approval/pin_approved_contract.py \
  --execution-arn "PASTE_PIPELINE_EXECUTION_ARN" \
  --approve \
  --note "Reviewed evaluation results; approved"

The note is optional. Omit --approve if you already approved the package in Studio. The command prints the contract's S3 URI. It copies the existing artifacts without retraining, recalibrating or choosing another cutoff. Identical retries are allowed; different content cannot overwrite an existing pin. Registry approval remains authoritative, even if contract files exist.

The downstream batch launcher receives that contract URI, verifies the package is still approved, applies the saved preprocessing and loads the pinned model. After Batch Transform returns raw scores, the launcher applies the cutoff from the pinned evaluation. Batch inference itself is separate work.

Artifacts and effects analysis

Versioned processes and outputs

The approval folder is identified by model package group, pipeline execution ID and registry package version. The contract's model_version is the registry package version, not the training artifact's v1 folder. Each artifact reference has a source_uri for the original and a uri for the pinned copy.

Green indicates added artifacts. The originals remain in their run folders. Pinned copies use S3-managed encryption, matching the team's approval implementation.
