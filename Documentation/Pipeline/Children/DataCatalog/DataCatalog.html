Feature overview

The data catalog stage registers the raw cell2cell CSV in Glue, then uses Athena to curate it into a typed, partitioned Parquet table and a training-ready view. It is a one-shot batch construction: once curated, the raw table is never read again.

Component diagram

Sequence diagram

  1. Terraform creates the Glue database (the catalog namespace).
  2. Terraform creates the cell2cell_raw external table over the raw CSV in S3. This is schema-on-read: OpenCSVSerde parses the quoted CSV, every column is typed STRING, and no data is moved.
  3. Terraform creates the Athena workgroup, which sets the query result output location (distinct from the table's own LOCATION).
  4. The operator runs run_curation.py, which submits 01_create_curated.sql to Athena.
  5. Athena resolves the raw table's schema from Glue, reads the raw CSV from S3, and executes the CTAS: casting every column to its real type, deriving churn_label and split, and writing the result as Parquet (partitioned by split) to a new S3 location.
  6. The CTAS registers the new cell2cell_curated table in Glue. cell2cell_raw was only ever read by this one query and is not used again.
  7. run_curation.py submits 02_create_view.sql, which creates vw_cell2cell_training — a view over cell2cell_curated filtered to split = 'train' with a non-null churn_label.

Versioned processes and outputs

This stage has one configured output version: CURATED_VERSION. It names the curated dataset's S3 directory. It does not version the SQL, create a run identifier, or give the Glue tables separate versioned names.

Changing v1 to v2 changes the destination, but the fixed table name still exists. This implementation has no automatic version migration or replacement procedure.

Column comparison

One row per column, one comparison column per dataset state. Future stages can extend the comparison horizontally using the same column names and change colors. Colors describe the change from the immediately preceding dataset state. Orange includes value normalization even when the type stays STRING; red here means excluded from the view, not deleted from Parquet.

The training view excludes three leakage columns (retentioncalls, retentionoffersaccepted, madecalltoretentionteam), the original churn text label, and split. The partition key split is represented by the S3 partition directories and exposed by the catalog; it is not an extra field inside each Parquet file. Rows below retain source-column order for comparison; the view's actual SELECT order starts with churn_label, then customerid.
