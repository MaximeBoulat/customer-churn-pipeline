Feature overview

The SageMaker pipeline starts from curated labeled Parquet. It runs preprocessing and Feature Store ingestion, trains XGBoost, evaluates it on the test split, and registers a model only when its AUC passes the quality gate. A registered model starts as PendingManualApproval; this does not approve or deploy it.

Component analysis

Diagram

Key AWS actors and concepts

SageMaker Pipelines coordinates jobs and records each execution. Training jobs fit models on temporary compute. A model package group holds registered model versions; each package points to a trained artifact and its inference image.

SageMaker Processing runs the preprocessing and ingestion scripts. A Feature Group defines feature records; its offline store writes them to S3 asynchronously. The online store is disabled.

Preprocess

Overview

  1. Read curated/cell2cell/{CURATED_VERSION}/split=train/ directly. The Athena training view is not used.
  2. Assign customers deterministically to approximately 70% training, 15% validation and 15% test, separately within each class. A customer must occur once. The fixed seed is 540.
  3. Exclude the three leakage columns and keep IDs, labels and partition information out of model features.
  4. Treat zero ages as missing. Add flags for zero ages, missing handset price, and an entirely missing usage record.
  5. Fit numeric medians, ServiceArea frequencies, and categorical levels on training rows only. Apply those values to every split. Other categorical fields are one-hot encoded with the first sorted category omitted.
  6. Write headerless, label-first CSVs, corresponding customer IDs, and preprocessing_parameters.json containing the fitted transformation and feature order.

Unseen ServiceArea values map to zero; unseen one-hot categories produce all zeros. Entirely missing numeric training columns use zero instead of a median. No probability recalibration is fitted here; the saved factor is 1.0.

Versioned processes and outputs

Ingest features

Overview

ingest.py checks group readiness and schema, then sends every processed row through PutRecord. Any ingestion failure blocks training. Successful ingestion means API acceptance; offline S3 delivery happens asynchronously.

Artifacts and effects analysis

Versioned processes and outputs

FEATURE_VERSION selects the group and offline prefix. Records carry the execution ID and event time. If emitted fields change, regenerate pipeline/schema.json and bump the feature version before applying Terraform.

No rows or columns change. The label is the target; numeric feature columns are the inputs. Test and holdout data are not read.

Evaluate

Overview

The model predicts probabilities for the test split. Evaluation reports AUC and uses a classification threshold of 0.5 for precision, recall, F1, accuracy and the confusion matrix. Recalibration is 1.0, meaning no adjustment.

Artifacts and effects analysis

Versioned processes and outputs

The evaluation report belongs to the same model version and execution as the trained artifact.

Quality gate

Overview

The gate compares test AUC with TF_VAR_auc_threshold, currently 0.60. Passing permits registration; failing ends the execution without registering a package. This is separate from the 0.5 classification threshold used in evaluation.

Artifacts and effects analysis

Versioned processes and outputs

No new artifact version is created. The pass/fail result is recorded in the pipeline execution.

S3 layout after the step

s3://customer-churn-pipeline-a81b79/
├─ models/cell2cell/{model-version}/{execution-id}/
│  └─ evaluation/evaluation.json       [READ]
└─ …

No S3 writes. Existing artifacts remain if the gate fails.

Dataset before and after

Unchanged; the gate reads a metric, not dataset rows.

Register model

Overview

A passing model is registered as PendingManualApproval. The package references the trained artifact, its inference image, the evaluation report and the fitted preprocessing parameters. Registration does not approve or deploy the model.

Artifacts and effects analysis

Versioned processes and outputs

SageMaker adds a numeric package version to the model package group. That number is independent of MODEL_VERSION.
