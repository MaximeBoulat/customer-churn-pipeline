Feature overview

This stage reads the curated labeled data, splits it into train/validation/test, fits preprocessing on training rows, and writes numeric model inputs. It also ingests those same features into an offline SageMaker Feature Group. The pipeline runs this stage through Preprocess and IngestFeatures.

Component diagram

Key AWS actors and concepts

SageMaker Processing runs our Python scripts on temporary AWS compute. A Feature Group defines the fields of stored feature records. Its offline store saves those records to S3 asynchronously and exposes them through a Glue table. The online store is disabled.

Sequence diagram

Preprocessing

  1. Read curated/cell2cell/{CURATED_VERSION}/split=train/ directly. The Athena training view is not used.
  2. Assign customers deterministically to approximately 70% training, 15% validation and 15% test, separately within each class. A customer must occur once. The fixed seed is 540.
  3. Exclude the three leakage columns and keep IDs, labels and partition information out of model features.
  4. Treat zero ages as missing. Add flags for zero ages, missing handset price, and an entirely missing usage record.
  5. Fit numeric medians, ServiceArea frequencies, and categorical levels on training rows only. Apply those values to every split. Other categorical fields are one-hot encoded with the first sorted category omitted.
  6. Write headerless, label-first CSVs, corresponding customer IDs, and preprocessing_parameters.json containing the fitted transformation and feature order.

Unseen ServiceArea values map to zero; unseen one-hot categories produce all zeros. Entirely missing numeric training columns use zero instead of a median. No probability recalibration is fitted here; the saved factor is 1.0.

Feature Store ingestion

ingest.py waits for the group to be ready, checks its schema against the processed features, and sends every train, validation and test row through PutRecord. It adds the customer ID, label, split name, execution ID and event time. An ingestion error fails the step and blocks training.

A successful step means all records were accepted by the API. Delivery into offline S3 files happens later. Training reads the processed CSVs directly, so it does not wait for that delivery or query Feature Store. Repeated executions append feature history; execution_id distinguishes their records.

Versioned processes and outputs

  • CURATED_VERSION selects the source Parquet directory.
  • PREPROCESSING_CONTRACT identifies the transformation rules. Each execution saves its own fitted parameters under pipeline/{execution-id}/process/contract/.
  • FEATURE_VERSION identifies the Feature Group schema. It is part of the group name and offline prefix.

The checked-in feature-store/schema.json starts from the team's existing 70-feature schema. All model features are stored as Fractional values to preserve median-imputed values; five additional fields describe each record. If preprocessing changes the emitted fields, regenerate the schema from real curated data and bump FEATURE_VERSION before applying Terraform. The ingestion step rejects a mismatch rather than silently dropping fields.

The group and its offline location persist across runs. Bumping the feature version changes the group name and replaces the group managed by Terraform; its old offline S3 files remain. Before a run there are no outputs for that execution; afterward there are three CSV splits, fitted parameters, identifiers, an ingestion report and accepted feature records.

Files and operation

preprocess.py contains the transformation; process.py reads and writes job files; ingest.py sends records. The pipeline calls these files directly. There is no second ingestion path.

Infrastructure and execution commands are documented in .

When the feature schema changes

From the repository root, with .env exported, download the actual curated labeled files and regenerate the schema. These are real data operations, not tests. Then bump TF_VAR_feature_version in .env, reload it, and review the pipeline Terraform plan.

uv sync
aws s3 cp "s3://${TF_VAR_output_bucket}/curated/cell2cell/${TF_VAR_curated_version}/split=train/" data/schema-input/ --recursive
uv run python feature-store/generate_schema.py --curated-directory data/schema-input

Use an empty local input directory for a new curated version so old files are not mixed in. The initial schema is carried from the team implementation; it has not been regenerated or executed in this repo yet.
